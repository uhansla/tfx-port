# TFX port: debugging log

A chronological record of the problems hit while getting CONFIG.EXE and TFX.DAT to run natively: what was tried, what each attempt showed, and what fixed it. Facts about the original program are in [TFX_CODE.md](TFX_CODE.md); this file is the journey.

Addresses are **load addresses** (code object at 0x400000, data object at 0x490000 for TFX.DAT / 0x430000 for CONFIG) unless marked *link*. Link address = load − 0x3F0000 for TFX code (data: − 0x3F0000 as well, since both objects move by the same amount).

### Checked and ruled out for the black view
- Time source and frame limiter (BIOS ticks advance; the loop is a normal limiter).
- Return-mismatch unwinding (only the expected number-formatting case, 0x47AE3F → 0x47AEF4).
- Missing data files (`global_5..8.tm` are genuinely absent from the CD; the whole mission set loads).
- The mission file lookup (`miss601.mis` exists and loads after DOS fallback).
- FPU state (stack top 0, control word 1272h, round to nearest).
- The heap-loaded code (a sprite blitter, not the renderer).

### Hypotheses that were open (resolved by rows 36–39)
1. Another mistranslated instruction class somewhere between the flight update and the draw dispatch (a full-interpretation comparison would settle this once the interpreter is fixed).
2. Self-modifying stores **through registers** into code (not detectable statically): stale immediates or jumps in the renderer.
3. The mode byte 0x4A347A meaning something else (e.g. a detail/render level chosen at start-up via a CPU benchmark or from TFX.CFG), with the real 3D switch elsewhere.

## Debug tooling reference

**Runtime environment variables**
| Variable | Effect |
|---|---|
| `TFX_DEBUG=1` | Heartbeat every second (EIP, VGA, palette, FPU, CRTC), function trace at exit, return-mismatch log, archive lookup names (with `INTERP=45804c` build) |
| `TFX_TRACE_INT=1` | Log every software interrupt and real-mode call |
| `TFX_SHOT=file.bmp` | Screenshot every second |
| `TFX_SCRIPT="ms action;..."` | Scripted input: `w` wait for no file I/O, `k SC` key, `r dx dy b` relative mouse, `m x y b`, `s file` screenshot (delays relative) |
| `TFX_CMDFILE=path` | Live command channel (lines appended while running) |
| `TFX_INTERP=lo-hi,...` | Run these code ranges in the interpreter |
| `TFX_DUMP=addr:len,...` | Dump guest memory on a crash |
| `TFX_TRACE_SB=1`, `TFX_SB_WAV=f` | Sound Blaster/DMA/PIC trace; record SB output |
| `TFX_TRACE_MUSIC=1`, `TFX_TRACE_RM=1` | Music driver calls and real-mode timer; real-mode instruction trace |
| `TFX_TRACE_OPL=1`, `TFX_OPL_WAV=f`, `TFX_TRACE_MIDI=1` | OPL register writes, record FM output, MIDI messages |
| `TFX_MIDI_DEVICE=name` | MIDI output device to use (substring of its name) |

**Live commands** (`dev/drive.sh ...`): `P SECONDS` sampling profile of the game thread (by function entered last and by instruction address), `k/d/u SC` key press/down/up, `r dx dy b` mouse, `shot NAME` (→ `work/NAME.png`), `p ADDR [n]` peek dwords, `b ADDR VAL` poke byte, `v X Y` displayed pixel and palette, `z`/`h` zero/dump the call histogram, `g` dump/reset the VGA write profile, `i ranges` set interpretation ranges, `c` log code bytes changed since load (also done on every crash), `f` frame rate since the previous `f` (with the mean and largest delay from page flip to present), `O key=value` change a tfx.ini display setting live, `W file` save the scaled window (`dev/drive.sh wshot NAME`; also with frame generation on), `S` native-renderer capture statistics, `m` int 33h calls by function and the mouse state, `q` quit (dumps the function trace). The `h` histogram includes interpreted calls.

**Crash dumps**: `TFX_DUMP="addr:len,..."` (hex) logs guest memory on a crash or fatal error.

**Tests**: `dev/tests/flags_test.c` (lazy flags, shifts, rotates, conditions and FPU conversions vs. the host CPU), `dev/tests/x87_test.c` (all x87 register forms and `[esi]` memory forms, interpreter vs. host FPU).

**Ghidra**: `dev/ghidra/import.sh`, `dev/ghidra/decompile.sh` (see PORTING_PLAN.md).

**Play tests** (`dev/play/`, game started with `TFX_CMDFILE`): `flighttest.sh` (fps, all views, weapons), `mode.sh NAME DY` (any Enrol-screen mode), `to_arming.sh`, `to_uncmd.sh`, `bisect2.sh` (interpretation-range bisection). `tools/contact.ps1` tiles screenshots into a contact sheet.

**Build-time options**: `XCFLAGS=-DESP_DEBUG` (stack balance check at every `ret`); `INTERP=addr,...` (always interpret those functions; logs archive lookups for 45804c); analysis results cached in `work/analysis_cache/` keyed on executable and analyzer source.

**Scripts**: `dev/run_tfx.sh` / `dev/run_config.sh` (run with logs), `dev/to_flight.sh` (boot to the Arcade cockpit with the saved pilot), `dev/calltree.sh FUNC`, `dev/callers.sh FUNC` (static call graph with live counts), `tools/disasm_at.py`, `tools/diag_reject.py`, `tools/didfs.py`. Sky and weather: `dev/play/to_sim.sh THEATRE WEATHER` (Simulator runway start), `dev/play/climb.sh` (take-off, climb, pause), `dev/play/sky_case.sh THEATRE WEATHER` (original vs native comparison), `dev/play/fps_case.sh normal|high` (frame rate, flip-to-present delay, time step), `tools/compare.ps1`; the cmdfile `D` command dumps the last captured frame (every primitive, with band corners and disc fills, and the HUD items); `w X Y` logs the code address that last wrote a displayed pixel; `U [Y0 Y1]` counts the displayed pixels still drawn by the game (owner UI) by the code that wrote them; `A DIR` saves the cockpit template from video memory (`BB80h`) and every sprite of the next frame as BMPs in the game's palette (transparent = magenta), with a `manifest.txt` of bank, index, caller, position and size.
